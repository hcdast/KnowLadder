## 1. 背景、现状与问题

仓库保留 `prototype/`独立演示，另有 `server/` NestJS + MongoDB真实服务和 `web/`真实前端；第一阶段运行与验证见技术架构方案第19节，阶段二教材/题库/私有文件续作已获授权并完成本地实施及必要验证，最终 WSL2 全套72项通过，真实验证及Windows历史限制见第18.1.1节，不代表生产或真实第三方材料获准开放。原型的学习数据仍只在内存，不导入真实数据库；测评、学情接口仍未实现。

本文件保留原型交互契约并记录实际交付。API 使用 NestJS、主数据库使用 MongoDB 为已确定的正式架构约束；原型使用内存演示服务，不能据此推断后端契约已实现或部署已获批准。

## 2. 目标、非目标与交付门槛

### 2.1 目标

- 让学生走通“章节 → 练习/测验 → 提交 → 结果 → 学情与建议 → 再学习”。
- 让内容编辑与审核者分别体验“教材章节 → 题目草稿 → 审核 → 发布”，观察发布前后学生可见性。
- 用可复现的场景验证断网、冲突、截止、待出分、缺少证据等状态，不只做正常页面跳转。
- 提供桌面与移动端可点击、可键盘操作的 Vue 原型供体验评审，不以静态截图冒充可交互交付。

### 2.2 非目标

本轮实现浏览器原型，不实现生产级登录、真实权限隔离、真实上传/扫描、MongoDB 事务、真实评分模型、支付、家校消息、教师/家长完整端或实际学生试点。原型演示能力不是正式产品能力，不用“前端隐藏字段”证明后端答案安全。

### 2.3 分阶段交付

| 阶段 | 产物 | 进入条件 |
| --- | --- | --- |
| 设计 | UI/UX 页面与组件规范、本文件交互契约与验收脚本 | 已获用户确认执行原型 |
| 浏览器原型 | 可运行 Vue 项目、演示内容、普通及异常场景、浏览器验证记录 | 已实现；验证证据与限制见第 12 节 |

## 3. 页面、入口与导航契约

页面 ID 是设计和验收的稳定标识；下表路由已在原型实现。桌面和移动导航使用同一语义，练习与考试页进入专注布局，保留明确返回路径及未保存提示。管理教材详情以 `/admin/textbooks?versionId=<id>` 打开，题库列表为 `/admin?type=question`，新建按钮生成 UUID 后进入编辑，不将 `new` 当成已有版本 ID。

| ID | 页面 | 建议路由 | 主要入口与出口 |
| --- | --- | --- | --- |
| S01 | 学生首页 | `/student` | 场景入口 → 继续章节/继续会话/学情推荐 |
| S02 | 教材目录 | `/student/textbooks` | 课本导航 → 选择版本及章节 → S03 |
| S03 | 章节阅读 | `/student/chapters/:chapterId` | 目录/推荐/错题 → 阅读 → S04；返回目录保留定位 |
| S04 | 练习设置 | `/student/practice` | 章节/练测导航 → 确认知识点、基础/提升/挑战 → S05；测验入口进入 S06 |
| S05 | 练习作答 | `/student/practice/sessions/:sessionId` | 创建或继续练习 → 作答、答题卡、交卷确认 → S08 |
| S06 | 测验说明 | `/student/quizzes/:quizId` | 首页测验入口/S04测验区域 → 开放时间、次数、时长、出分规则 → S07 |
| S07 | 测验作答 | `/student/quiz/sessions/:sessionId` | 开始/继续测验 → 保存、计时、交卷确认 → S08 |
| S08 | 提交与结果 | `/student/submissions/:submissionId` | 已受理提交 → 处理中/待发布/结果 → S09、S10或原章节；未知受理停留来源页确认 |
| S09 | 学情推荐 | `/student/growth` | 成长导航/结果 → 查看证据与建议 → S03/S04/S06 |
| S10 | 错题 | `/student/mistakes` | 错题导航/结果 → 原结果/章节/创建新练习，不覆盖原成绩 |
| A01 | 内容工作台 | `/admin` | 编辑或审核演示入口 → 待办、筛选、版本状态 → A02/A03/A04 |
| A02 | 教材章节 | `/admin/textbooks` | 工作台 → 教材版本草稿/章节结构/知识关联/授权与资源状态 → 保存、送审至A04；关联题目进入A03 |
| A03 | 题目编辑 | `/admin/questions/:versionId` | 题库列表/新建 → 草稿、预览、关联知识点 → 送审/A04；已发布只读，勘误新建版本 |
| A04 | 审核发布 | `/admin/reviews/:resourceType/:versionId` | 待审列表 → 按教材/题目类型核验版本、关联与授权 → 退回/发布 → 工作台；resourceType 仅允许教材版本和题目版本 |

`/` 为演示说明与场景选择，不是生产登录页。提供“学生”“内容编辑”“内容审核”明确标注的演示身份；切换身份仅用于评审，同一草稿的创建者不能在该演示流程中自审发布。真实身份和角色分配由后续服务端实现。

浏览器刷新或直接打开未知 ID 时显示“此演示记录不存在”及返回入口，不自动跳到无关成绩。深链若缺少场景上下文，应提示选择相应场景，不静默创建新会话。正式接入后路由守卫只改善体验，NestJS 仍负责鉴权。

## 4. 三条完整交互路径

### 4.1 学生练习闭环

1. 在演示入口选择“首次学习”或“继续学习”，全局可见“演示模式 · 非真实学习记录”。
2. S01 → S02 → S03，教材以明确标识的原创数学示例代替未经授权的教材扫描件。
3. S03 → S04，确认章节范围、难度和题量；无题时解释原因并返回章节，不偷偷扩大范围。
4. S05 展示题目、答案控件、题号导航和保存状态；首期原型覆盖单选、多选、确定性数值填空，不做无法验证的公式等价性或主观题自动评分。
5. 在 S05 本页打开交卷检查面板，显示已答/未答清单，可关闭并定位题目；确认后冻结本次请求和幂等键。提交处理中或受理未知时仍在 S05，保存并发处理见第 5 节。
6. 提交受理后进入 S08；先出现处理中，随后按场景显示结果或错误。演示结果必须标注“示例批改”，不能暗示已调用评分服务。
7. S08 → S09 查看有样本说明的示例反馈；建议项能进入对应章节或新练习。S10 重练产生新会话，原结果保持不变。

### 4.2 测验及异常恢复

1. S06 明确题量、允许次数、时间窗口、时长和成绩发布时间；开始操作失败时不能先扣除前端显示的次数。
2. S07 与练习使用不同模式：考试期间不出现提示、解析、对错标记或能导向当前试卷答案的推荐。
3. 答题卡支持已答/未答/当前题，状态同时用文字或形状表达，不能只依赖颜色。
4. 时间提示来自服务端时间契约；原型由场景时钟模拟并标识。暂停标签页后恢复应重新计算，不靠每秒递减次数判断有效时间。
5. 截止时停止编辑，显示“已到截止时间，正在确认提交状态”；不能仅凭本机倒计时宣布交卷成功。演示场景返回已保存答案的截止提交或待确认状态。
6. S08 在待发布时只显示处理/发布状态，不展示分数、答案或能推断该考试结果的学情细节。同一演示运行期间回访已结束会话不重新开始、不新增计分；原型刷新会重置场景，按第 6.2 节显式提示，不能据此证明真实会话持久化。

### 4.3 内容编辑与审核

1. 编辑身份从 A01 → A02 编辑教材版本草稿，维护章节结构、标题、正文示例、知识关联及授权元数据；保存后可送审至 A04，已发布教材只允许新建版本。原型文件选择只展示文件名、大小和扫描状态演示，不上传真实文件、不称为已保存云端。
2. A03 使用题型表单编辑原创示例，展示学生预览与仅管理端可见的答案/评分信息；缺必填、知识关联或授权时明确定位错误。
3. 草稿保存后可以送审；审核中版本冻结，退回后才能继续修改；该状态转换为候选管理接口需求，尚未存在于技术 API 清单。
4. 切换到不同的审核演示身份，在 A04 按资源类型比较版本并审核；拒绝需原因，批准仍须资源 ready、授权有效且作者不是审核者。教材版本检查完整章节结构及知识关联；题目版本另检查答案与评分规则，不能要求教材填写题目答案。每次审核固定资源类型及版本 ID，变更后必须重新预览。
5. 发布成功后更新内容状态，学生演示目录只出现已发布且授权的版本；勘误新建草稿，旧会话保留原快照。

## 5. 交互状态机与异常反馈

### 5.1 作答保存和提交

客户端业务状态与保存状态分离：会话使用技术方案的 `in_progress/submitted/expired/cancelled`；本地使用 `clean/dirty/saving/save_failed/conflict/submitting/confirmation_pending` 描述界面，不能把后者直接写成服务器会话状态。

| 触发/状态 | 界面反馈 | 允许操作与约束 |
| --- | --- | --- |
| 修改答案 `dirty` | “有更改尚未保存” | 保留本次编辑；快速切题不丢草稿 |
| 正在保存 `saving` | “正在保存”及最近成功时间 | 同会话保存串行化；每次使用最新确认 revision，不能多个请求共用旧修订并盲目覆盖 |
| 保存成功 `clean` | “已保存” | 仅当响应对应的草稿版本仍为当前版本时转 clean；保存期间产生新编辑则保持 dirty 并排入下一次保存。只依据成功响应确认，原型响应标识为模拟 |
| 保存失败/断网 | 持续提示“尚未保存，请勿关闭页面” | 原型保留内存草稿，可重试；不默认离线可交卷；离开时提示可能丢失 |
| `409 REVISION_CONFLICT` | 显示当前本地答案与重新获取的服务器版本差异 | 允许保留服务器版，或在仍可编辑时明确确认用本地草稿重新保存；禁止自动覆盖 |
| 点击交卷 | 未答确认 → “正在提交” | 停止产生新保存请求；等待在途保存响应，解决未知保存/冲突后，以最新 revision 提交最终草稿，不靠节流计时器是否触发判断完成 |
| 已受理 `202` | “已提交，正在批改” | 进入 S08，禁止再次编辑；不立即显示分数 |
| 响应丢失/结果未知 | “正在确认是否提交成功” | 保留同一 key 和原请求正文，重新查会话/按原请求恢复；未确认前不能换 key 或修改请求后重发 |
| 已确认旧请求未提交、仍可编辑 | 恢复草稿与状态 | 必须确认旧请求已结束且不可能迟到生效，不能仅凭一次读取 in_progress 判定。若需变更正文或 revision，再作为新操作使用新 key |
| 截止 `SESSION_DEADLINE_PASSED` | “已到截止时间，正在获取最终状态” | 不接收补答；读取服务端截止提交，未确认不能展示成功 |
| 批改失败/待复核 | “批改暂未完成”/“待复核” | 显示查询状态与返回入口，不要求重新交卷，不虚构分数 |
| 报告落后/无证据 | “更新中，当前结果截至…”/“待诊断” | 不以空值显示 0%，不把旧报告表示为新提交结果 |

正常提交只在一次最终请求完全确定后生成幂等键，原请求对象不可随界面草稿变化。页面离开提示不能保证浏览器崩溃、关闭或操作系统回收时保留数据，界面不得承诺“永不丢失”。

### 5.2 通用及管理状态

- `401`：清除当前敏感展示，提示重新认证；原型跳回演示入口并说明不是实际登录。
- `403/404`：统一资源不可访问提示；不透露其他学生、班级或未授权教材存在性。
- `422`：字段级错误与页面错误摘要同时给出，焦点移至摘要，链接定位字段。
- `429`：遵守 `Retry-After`，显示何时可重试；停止无限轮询。
- `503`：明确未确认受理，提供重试与 `request_id`，不把未知结果断言为事务失败。
- 内容 `draft/review/published/retired` 与文件 `pending/quarantined/ready/deleting` 分开呈现；题目完成编辑不代表附件通过扫描或拥有版权。
- 空列表区分未创建、筛选无结果、数据不足和无权查看，不用统一“暂无数据”掩盖错误。
- 加载使用固定布局占位；失败保留上下文与明确重试按钮，禁止旋转图标无限等待。

## 6. 原型架构与文件影响

### 6.1 模块与依赖

原型采用 Vue 3 + TypeScript + Vite、Vue Router，共享设计 token，学生和管理使用独立导航。使用原生表单和 `dialog`，未引入额外 UI 组件库；依赖版本由 `package-lock.json` 锁定。

实际源码结构（共享布局在 App.vue，类型与对应服务共置，不保留空目录或伪 HTTP 适配器）：

```text
prototype/
  package.json
  package-lock.json
  index.html
  vite.config.ts
  tsconfig.json
  src/
    main.ts
    App.vue
    router.ts
    styles/tokens.css
    components/ConfirmDialog.vue
    features/LandingView.vue
    features/NotFoundView.vue
    features/student/StudentView.vue
    features/student/SessionView.vue
    features/student/ResultView.vue
    features/admin/AdminView.vue
    services/core.ts
    services/catalogue.ts
    services/student-service.ts
    services/admin-service.ts
```

组件只调用 service 契约，不直接读取场景答案。演示服务承担确定性场景响应；真实 HTTP 适配器等后端接口确认后再实现，不能留下伪成功的生产适配器。学生题目组件不包含正确答案属性，正确性只在演示结果响应中按状态返回。但演示代码最终可被浏览器检查，因此这不是安全隔离证明。

### 6.2 数据流、模型和重置

`场景入口 → 演示服务状态 → 页面视图模型 → 用户操作 → 演示响应 → 可见状态`。

- 原型使用 UUID 字符串标识、时间戳、revision、冻结请求键及独立的报告证据快照；前端服务是内部演示接口，不冒充 NestJS 的 JSON DTO。正式联调时仍须按第 7 节及技术方案实现 snake_case、分数字符串、request_id 与 source_watermark 等契约。
- 场景数据包括教材/章节/题目展示版本、会话/题项/草稿、提交与发布状态、学情证据水位、内容工作流与身份能力。
- 示例使用原创题目、虚构身份，不导入真实学生、教材扫描件、密钥或第三方受限素材；演示数字均标示来源为示例。
- 作答、内容修改与成绩仅保存在内存。URL 的 `scenario=returning` 只记录非敏感的演示场景选择，刷新恢复该场景初始示例；不保存用户输入或身份凭据到 localStorage。运行中生成的会话 ID 刷新后不存在时显示安全返回页，不自动重建原成绩；返回首页可继续初始场景。入口和草稿页均提示刷新风险。
- 显式“重置演示”二次确认后统一清空所有演示更改，不能只刷新首页却遗留成绩和发布记录。重置提示不是生产数据删除功能。

### 6.3 当前文档变更范围

原型阶段新增prototype源码、lockfile及自动构建产物；随后真实账号第一阶段另建server/web/ops及认证schema迁移，未修改原型数据来源。历史原型验证见第12节，当前真实系统验证见技术架构第19节；无生产部署。

## 7. API 对接与缺口登记

API业务路径及阶段边界见技术架构方案第5、17—19节。下表保留原型缺口登记：身份认证已在独立真实应用实现，其他业务仍待分阶段落地；不能因存在API设计就宣称实现完成。

| 原型能力 | 已有设计契约 | 正式实施前缺口/约束 |
| --- | --- | --- |
| 身份、组织 | `GET /me`及第17.6节认证接口 | 已在server/web实现真实登录、CSRF、改密、退出、续期和组织选择；prototype身份切换仍只演示，不与正式账号混用 |
| 教材/阅读 | `GET /textbook-editions`、`GET /chapters/{id}` | 教材章节树、阅读进度及文件鉴权下载接口未完整定义 |
| 创建练习/测验 | `POST /practice-sessions`、`GET /quizzes/{id}`、`POST /quizzes/{id}/sessions` | 可用练习范围与测验列表、恢复会话入口需要查询契约；不从前端猜测权限 |
| 作答/交卷/结果 | `GET /sessions/{id}`、`PUT /sessions/{id}/answers/{session_item_id}`、`POST /sessions/{id}/submissions`、`GET /submissions/{id}` | 补足服务端时间、截止/发布状态、按幂等请求恢复的响应约定；不私自新增正式 URL |
| 学情/推荐/错题 | `GET /me/mastery`、`GET /me/reports`、`GET /me/recommendations`、`GET /me/mistakes` | 必须携带证据水位、发布时间约束与合法跳转目标；推荐失效时解释并重新获取 |

## 8. 安全、兼容性与性能

- 原型启动只默认本机访问，不接生产域名、真实凭据或公网分析 SDK。若需分享，先确认访问范围并保持演示标识；不把原型配置直接用于生产。
- 真实产品凭据按技术方案的 HttpOnly/Secure Cookie 与 CSRF 防护处理，不存 `localStorage`；组织或角色切换必须清理前一上下文的缓存、请求结果与敏感视图。
- 不使用未清洗的富文本 HTML；公式、外链、图片来源和文件名按不可信输入处理。管理编辑预览也不能绕过 XSS 约束。
- 作答用原生语义表单，键盘能完成全流程；数学表达具备文本/可访问表达，不仅渲染为图片。
- 响应式和可访问性具体规则见 UI/UX 方案；原型验证至少覆盖 390px 手机与 1440px 桌面，并检查 320px 窄屏和 200% 缩放。不声称未测试的浏览器已兼容。
- 列表分页、路由按需加载、长列表控制渲染量、题图约束尺寸；避免为普通进度展示引入大型图数据库可视化/图表依赖。
- 结果状态查询有上限及退避，切换页面取消无用查询；等待超过窗口后给手动刷新入口，不形成后台无限轮询。轮询周期和性能预算待实际原型测量确认。
